# MYSS — Make Yourself Super Smart

Telegram Mini App: библиотека практического опыта выдающихся людей.

Пользователь выбирает человека и получает не биографию, а компактно собранный разбор: как этот
человек работал, какие принципы использовал, какие решения принимал, на чём ошибался и что из этого
можно применить сегодня.

Главный принцип проекта: **ничего не выдумывается**. Каждое существенное утверждение связано с
источником, а материал проходит статусы `draft → review → verified → published`.

## Архитектура

Единое Next.js-приложение (App Router) — фронтенд, API и админка в одном сервисе. Отдельные
микросервисы не используются: проект должен оставаться простым в поддержке.

```
prisma/
  schema.prisma              схема базы
  migrations/                SQL-миграции
content/
  categories.json            категории
  master-list.tsv            мастер-лист людей (500+)
  people/<slug>.json         полные профили с источниками
scripts/
  seed.ts                    загрузка контента в базу
  validate-content.ts        проверка контента до загрузки
  lib/master-list.ts         чтение мастер-листа
src/
  app/                       страницы и API-роуты
    api/                     REST API
    admin/                   административная часть
  components/                UI-компоненты
  lib/                       схемы контента, утилиты, Prisma, логирование
  server/                    авторизация, запросы, генератор «Мой день»
    telegram/initData.ts     проверка подписи Telegram
tests/                       тесты критической логики
```

**Стек:** Next.js 15, React 18, TypeScript, Tailwind CSS, Framer Motion, Prisma, PostgreSQL.

## Быстрый старт

```bash
git clone <repository-url>
cd MYSS
npm install

cp .env.example .env
# заполните DATABASE_URL и остальные переменные

npm run db:migrate        # применить миграции
npm run validate-content  # проверить контент
npm run seed              # загрузить категории, мастер-лист и профили

npm run dev               # http://localhost:3000
```

Для работы вне Telegram в разработке установите `ALLOW_DEV_AUTH="true"`. В production этот флаг
игнорируется — там обязательна подпись Telegram.

## Переменные окружения

Полный список — в `.env.example`. Файл `.env` **никогда не коммитится**.

| Переменная | Назначение | Обязательна |
| --- | --- | --- |
| `DATABASE_URL` | строка подключения к PostgreSQL | да |
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather; используется для проверки `initData` | да в production |
| `NEXT_PUBLIC_APP_URL` | публичный URL приложения без слэша в конце | да |
| `TELEGRAM_WEBAPP_URL` | URL Mini App, зарегистрированный в BotFather | да |
| `ADMIN_SECRET` | секрет для служебного доступа к админ-API | да |
| `ADMIN_TELEGRAM_IDS` | Telegram ID администраторов через запятую | да |
| `TELEGRAM_WEBHOOK_SECRET` | секрет вебхука бота | нет |
| `ALLOW_DEV_AUTH` | разрешить вход без Telegram (только локально) | нет |

## База данных

PostgreSQL + Prisma. Основные сущности: `users`, `people`, `categories`, `courses`,
`course_sections`, `facts`, `principles`, `habits`, `quotes`, `cases`, `mistakes`, `sources`,
`claims`, `user_progress`, `user_completed_sections`, `favorites`, `daily_routines`,
`routine_items`, `recommendations`, `usage_events`.

```bash
npm run db:migrate     # применить миграции (production)
npx prisma studio      # просмотр данных
npx prisma migrate dev --name <название>   # создать новую миграцию
```

Индексы созданы по `slug`, `name`, `country`, `status`, `era`, `user_id`, `person_id`, а для поиска
по подстроке используется GIN-индекс `pg_trgm` по полю `searchText`.

### Claim-система

Каждое существенное утверждение хранится как `claim` со ссылками на источники, статусом и уровнем
достоверности. Факты, принципы, привычки, цитаты, кейсы и ошибки ссылаются на свой claim. Это
позволяет удерживать качество базы при масштабировании.

## Контент

### Мастер-лист

`content/master-list.tsv` — более 500 реальных людей: slug, имя, роль, страна, регион, эпоха,
категории, годы жизни. Все попадают в базу как черновики (`draft`) и не показываются публично.

### Профили

`content/people/<slug>.json` — полный материал: разделы курса, факты, принципы, привычки, цитаты,
кейсы, ошибки, выводы, действия на сегодня и источники. Каждый факт и каждая цитата ссылаются на
ключ источника из массива `sources` того же файла.

Опубликовать профиль (`"status": "published"`) можно только если есть изображение, источники,
факты, принципы, раздел с ошибками, 5–10 пунктов «Что я бы забрал себе» и 1–5 действий «Попробуй
сегодня». Это проверяется схемой и скриптом валидации.

### Загрузка

```bash
npm run seed
```

Скрипт идемпотентен: профили перезаписываются из файлов, уже обогащённые записи не сбрасываются в
черновики.

## Валидация контента

```bash
npm run validate-content
```

Проверяет: дубликаты slug и имён, структуру по схемам, существование категорий, ссылки на
несуществующие источники, цитаты без источника, дублирующиеся цитаты, некорректные связи `related`,
несоответствие имени файла и slug, полноту обязательных разделов у публикуемых профилей.

Скрипт завершается с ненулевым кодом при наличии ошибок — его удобно ставить в CI.

## Настройка Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен.
2. Укажите токен в `TELEGRAM_BOT_TOKEN`.
3. Зарегистрируйте Mini App: `/newapp` в BotFather, URL — значение `TELEGRAM_WEBAPP_URL` (HTTPS).
4. Установите вебхук бота:

```bash
curl -X POST "https://api.telegram.org/bot<TOKEN>/setWebhook" \
  -H "content-type: application/json" \
  -d '{"url":"https://<ваш-домен>/api/telegram/webhook","secret_token":"<TELEGRAM_WEBHOOK_SECRET>"}'
```

Авторизация выполняется только через Telegram. Сервер проверяет подпись `initData` по алгоритму
HMAC-SHA256 и никогда не доверяет `user_id`, присланному клиентом. Отдельной регистрации нет.

Диплинки: `https://t.me/<bot>?startapp=<slug>` открывает страницу конкретного человека.

## Админка

Доступна по адресу `/admin` пользователям, чей Telegram ID указан в `ADMIN_TELEGRAM_IDS`.
Служебный доступ к API — по заголовку `x-admin-secret`.

Возможности: поиск по базе, фильтрация по статусу, просмотр наполнения профиля, замена изображения,
смена статуса и уровня достоверности, просмотр источников и claims, публикация и снятие с
публикации. Публикация блокируется, если нет источников, фактов или изображения.

Массовое наполнение выполняется через файлы `content/` и команды `validate-content` + `seed`.

## Деплой на Render

В репозитории есть `render.yaml` — Render создаст веб-сервис и базу PostgreSQL автоматически.

1. Подключите репозиторий в Render (New → Blueprint).
2. Render применит `render.yaml`: создаст `myss-db` и сервис `myss`.
3. Заполните переменные, помеченные `sync: false`: `TELEGRAM_BOT_TOKEN`, `NEXT_PUBLIC_APP_URL`,
   `TELEGRAM_WEBAPP_URL`, `ADMIN_TELEGRAM_IDS`. `ADMIN_SECRET` и `TELEGRAM_WEBHOOK_SECRET`
   генерируются автоматически.
4. Сборка: `npm ci && npm run build`. Запуск: `npm run start:migrate` — миграции применяются перед
   стартом.
5. Health check: `/api/health` (проверяет и доступность базы).
6. После первого деплоя загрузите контент:

```bash
# в Render Shell
npm run seed
```

Приложение работает независимо от компьютера владельца и обращается к production-базе, а не к
localhost.

## API

Публичные:

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/health` | проверка работоспособности |
| GET | `/api/people` | список с фильтрами `category`, `country`, `era`, `q`, `sort`, `page` |
| GET | `/api/people/:slug` | человек с курсом, источниками и рекомендациями |
| GET | `/api/categories` | категории с числом опубликованных людей |
| GET | `/api/categories/:slug` | категория и её люди |
| GET | `/api/search?q=` | поиск |
| GET | `/api/random` | случайный человек |
| GET | `/api/compare?slugs=a,b` | сравнение 2–3 человек |

Требуют подписи Telegram (`x-telegram-init-data`):

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/me` | профиль, статистика, прогресс |
| GET/POST | `/api/progress` | прогресс и отметка разделов |
| GET/POST | `/api/favorites` | сохранённое |
| DELETE | `/api/favorites/:id` | убрать из сохранённого |
| POST | `/api/saved-quotes`, `/api/saved-cases` | сохранение цитат и кейсов |
| GET | `/api/routine` | распорядки пользователя |
| POST | `/api/routine/generate` | собрать день |
| DELETE | `/api/routine/:id` | удалить распорядок |

Админ (Telegram ID из `ADMIN_TELEGRAM_IDS` или `x-admin-secret`):

| Метод | Путь |
| --- | --- |
| GET/POST | `/api/admin/people` |
| GET/PATCH | `/api/admin/people/:slug` |

Ошибки возвращаются человеческим текстом; технические детали и stack trace пишутся только в логи.

## Правила работы с контентом

Эти правила — часть продукта, а не рекомендация.

1. **Не выдумывать.** Факты, цитаты, привычки, статистика и истории добавляются только при наличии
   источника. Если подтверждения нет — материал не публикуется.
2. **Цитаты.** Только дословные и подтверждённые, с указанием источника. Если дословность под
   сомнением — используется пересказ без кавычек (`"isVerbatim": false`).
3. **Привычки.** Распорядок человека не реконструируется. Фиксируются только подтверждённые
   привычки.
4. **«Мой день».** Чужое расписание никогда не копируется буквально. Из привычки извлекается
   принцип, который адаптируется под ограничения пользователя. Для каждого блока показывается
   источник идеи, связь с человеком и способ адаптации.
5. **Без культа личности.** У опубликованного профиля обязателен раздел с ошибками и спорными
   решениями.
6. **Без выдуманных данных.** Никаких фиктивных пользователей, отзывов, статистики и популярности.
   «Популярное» строится только на реальных событиях использования; если данных нет — блок не
   показывается.
7. **Авторские права.** Большие фрагменты защищённых материалов не копируются. Основной формат —
   собственный краткий пересказ, структурирование и анализ с короткими проверенными цитатами.
